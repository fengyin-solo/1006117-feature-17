# 盾构隧道掘进施工管理平台

面向盾构机台账、掘进环次、管片拼装、同步注浆、渣土外运、地表沉降监测与轴线纠偏的一体化盾构隧道施工管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `shield-tunnel-construction:entries` 这一项，或调用 `resetModule(模块)`。

## 地表沉降监测域（取数、补测、报警）

沉降页、建筑监测页、运营概览三处的报警口径共用同一套实现，文件在：

- `frontend/src/api/monitor-service.ts`：排期、取数/重试、补测游标、读数幂等落库、越限报警、同源汇总、权限。
- `frontend/src/data/monitor-store.ts` / `seed-monitor.ts`：读数明细、取数异常、测区事件、补测游标（localStorage
  键 `shield-tunnel-construction:settlement-monitor:v1`），与主表分开存放。

约定的业务口径：

- **排期**：首测应测日 = 布点日期 + 监测频次；之后 = 最近监测日 + 频次。到点未测进「待补测」。
- **取数**：逐点 1 次取数 + 2 次重试；重试仍失败只记一条取数异常（含原因、尝试次数），
  **绝不顶替上一轮累计沉降/速率/最近监测**。整区先探一针，整区未测 / 整区失败直接在页面交代空态与原因
  （区分「没测量」与「没取到」），不再逐点白重试、不停在加载中。
- **补测**：批量游标每点落盘，中断后可从断点继续，`done` 里的测点不重测。
- **幂等**：同一测点 + 同一监测日期全库只保留一条读数，重复提交覆盖且不翻倍；存储写失败时读数明细回滚、
  入参原样退回，不留半条。
- **报警**：累计沉降或沉降速率达到测点自身限值即自动报警（限值只有本项目「监测负责人」可改）；
  报警结论落到测点清单，建筑监测页与运营概览都从 `getMonitoringSummary()` 同源派生，不各算一遍。
- **存量测点**：登记时按布点日期补进台账并直接参与排期；同编号不可重复布点。
- **身份**：页头可切换「监测负责人 / 值班员」；改预警阈值与初始高程仅监测负责人可操作。
- 页头提供取数链路演练开关（整区未测 / 整区取数失败 / 单点失败），用于验收空态与重试行为。
